# 协议与证据边界

字段和编码的公开实现位于 [protocol.cpp](../src/agent/protocol.cpp)、[protocol.hpp](../src/agent/protocol.hpp) 与 [model.hpp](../src/common/model.hpp)。实现参考 HiMOS 1.6.1 的软件行为及开发期间的回包观察。本仓库不附带原厂程序或分析运行时。

证据分开记录：

| 等级 | 范围 |
|---|---|
| 代码定义 | 本仓库的帧收包、CRC、字段偏移、缩放、发送参数和显示映射 |
| 历史单机观察 | 一台 DM850G、固件显示 V34.26.06.23 的状态、规格及序列号回包 |
| 待确认 | 其他型号／固件、传感器位置与精度、故障位、初始化必要性及不查询时自然回传的因果关系 |

代码可解释某字段，不等于所有固件已支持或测量精度已确认。历史观察不能代替当前电量、界面或恢复流程的运行验证。

## 串口与帧

当前默认 115200、8N1、无流控、DTR／RTS 关闭。端口按用户选择和设备标识确定，不向全部 COM 口发送探测。

~~~text
55 7E | L TYPE DATA... | CRC8 | AE
~~~

当前接收布局总长为 L+4。RX CRC-8 覆盖从 55 7E 帧头到数据区末尾，不含 CRC 和 AE；TX CRC 从 L 开始，不含帧头。参数为 poly=0x07、init=0、refin/refout=false、xorout=0。

收包器处理拆包、粘包、噪声和尾部残片。长度不合法、CRC／帧尾失败不更新读数；不把数据中的 AE 单字节当完整帧结束。接收缓存上限64KiB，原始候选诊断最多32条且16KiB，不持续写原始帧到磁盘。

当前历史接收观察涵盖类型0x02、0x03、0x04、0x05。收到的0x04语义仍未知，只计入诊断；不要与发送方向的信息查询类型混为一谈。

## 状态响应 0x02

数据区从 TYPE 后开始，最少28字节；下面U16均为小端。

| 偏移 | 内容 | 换算与单位 |
|---:|---|---|
| 0 | +3.3V | U16÷1000，V |
| 2 | +5V | U16÷1000，V |
| 4 | +12V | U16÷1000，V |
| 6 | +5V SB | U16÷1000，V |
| 8 | 原始风扇模式 | U8，只作诊断 |
| 9～11 | 保留字节 | 原样诊断，不解释 |
| 12 | 输入功率 | U16÷20，W，交流输入 |
| 14 | 输入频率 | U16×0.1，Hz |
| 16 | 高压区温度 | U16÷256，℃ |
| 18 | 低压侧温度 | U16÷256，℃ |
| 20 | 环境温度 | U16÷256，℃ |
| 22 | 输入电压 | U16×0.1，V |
| 24 | 风扇转速 | U16×30，RPM |
| 26 | 原始故障码 | U16，位含义未知 |

0 RPM 是可保留的读数。三种温度沿用软件区域名称，不能据此确定探头物理位置。电量是 Agent 根据输入功率的本地派生值，不是状态响应中的设备电表字段。

## 规格与序列号

0x03 数据区最少25字节。型号为前8字节字符串；额定功率在偏移14，为U16大端，与实时状态的小端不同。额定电流、电压范围、质保、认证、固件原始字段和日期／厂商布局由 parse_info 解释。固件日期分量不被当作生产日期。

0x05 读取前15字节字符串作为设备序列号。新会话重新获取信息，不能让缓存的上一设备身份冒充当前设备。规格中的电流是额定值，不是实时电流。当前没有可靠的实时输出功率、电流、效率或功率因数来源。

## 发送范围

发送类型0x04用于信息查询，选项为0x00及0x35；控制器打开连接后按现有顺序发送，响应按类型处理，不依赖固定回包顺序。这些查询是否为持续回传的必要条件仍待确认。

类型0x16仅用于用户手动应用的回传间隔，范围1000～3000ms、步长500ms。发送完成不表示设备确认。源码没有风扇模式、曲线、清灰或清除故障码的发送入口。
